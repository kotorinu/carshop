# テスト

**ZIPを作って渡す前に、必ずここを両方通すこと。**
実際にChromiumへ拡張機能を読み込んで、案件探し〜フォーム入力まで一通り動かす。

```bash
npm run apply:test        # 単体テスト（採点・募集要項の読み取り・応募文・HTML読み取り）… 189項目
npm run apply:test:e2e    # 通しテスト（本物のChromium＋拡張機能）… 108項目
```

通しテストには Playwright が必要:

```bash
npm i -D playwright jsdom
CHROME_PATH=/path/to/chrome npm run apply:test:e2e   # Chromeの場所を指定する場合
```

## 何をテストしているか

| ファイル | 内容 |
|---|---|
| `unit.mjs` | **案件の状態管理（同じものが二度と出てこないこと）**、6つのチェック項目の◯×不明、危険案件、禁止媒体、マスト条件、金額の読み取り、打ち消し表現、**募集要項の読み取り（指定項目・合言葉・字数制限・会社名・理念）**、応募文（全9カテゴリ）、AI臭チェック、一覧・詳細のHTML読み取り |
| `run.mjs` | 拡張機能の起動、ポップアップ、巡回、詳細取得、マスト判定（15案件）、合格だけタブで開く、**開いたタブで応募文が出来上がっていること**、**募集要項の指示を守っていること**、応募文の品質、フォーム自動入力、**送信ボタンを押していないこと**、応募済み記録、設定変更の反映、二重収集の防止、設定画面、**4種類のHTML構造への耐性**、**状態管理（応募済みが二度と出てこない・一度開いた案件を開き直さない・条件変更で人の判断を上書きしない）** |
| `fixtures/` | 実物そっくりのテスト求人サイト。15案件が全ルールを網羅し、媒体ごとにHTMLの作りを変えてある（divカード／表／短いリンク／入れ子＋ヘッダーの罠） |

## これまでに見つけた不具合（再発防止のため残している）

| 症状 | 原因 |
|---|---|
| 「巡回を始めています…」で固まる | サービスワーカーで動的import（禁止）を使っていた |
| 一覧の全案件が1件目と同じ内容になる | カードの切り出しを文字数だけで判断していて、情報の少ないカードのとき一覧全体を掴んでいた |
| 「新規開拓は一切ありません」を自己獲得型と誤判定 | 打ち消し表現を読んでいなかった／その後、打ち消し除去とアポ譲渡型の検出がぶつかっていた |
| メール・電話・住所がフォームに入らない | 配布用ZIPとリポジトリで同梱プロフィールが違っていた（`build.mjs` に一本化して解消） |
| 詳細URLのidにポート番号を拾う | URL全体から数字を取っていた |
| 募集要項の指定項目を読み取れない | ブラウザのinnerTextはHTMLの改行を空白に潰すため、箇条書きが1行になっていた。行で区切る前提だった |
| 「お名前・年齢・…を記載」の1文形式で最初の項目が落ちる | 区切り文字より前の部分を捨てていた |
| プロフィールが「?」のままの項目を「答えられた」と扱う | 未記入判定をしていなかった |
| 保存済みの応募文を開くと読み取り結果が消える | 応募文だけ保存して、募集要項の読み取り結果を保存していなかった |
| 字数制限が厳しいと会社の言葉が消える | 段落を削る順番が悪く、短い型に切り替える仕組みが無かった |
| ヘッダーに同じ案件へのリンクがあると一覧全体を掴む | 「別の案件を含まない親」で判定していたため、同じidのリンクではすり抜けた。body/main/header等の構造の区切りでも止めるようにした |
| 「A・B・C・Dを記載してください」の項目が多いと合図を見落とす | 合図の検出で文字数の上限が短すぎた |
| ポップアップの設定欄が無く画面が真っ白になる | HTMLに要素が無いまま値を代入して例外になっていた |
